# خدمات (Khadamat)

**كل خدمة تحتاجها... في مكان واحد.**


### تشغيل الإنتاج / Railway

عند تشغيل الخادم، يتم تطبيق الـ migrations وتشغيل `seed` الأساسي تلقائيًا وبشكل idempotent؛ لذلك لا يلزم تشغيل `npm run seed` يدويًا بعد كل نشر. يشمل ذلك أقسام وخدمات الكتالوج وحساب المدير الأول والإعدادات الافتراضية.

في Railway، لأن SQLite تعتمد على نظام ملفات، يجب ربط **Volume دائم** بمسار قاعدة البيانات (`DB_PATH`) حتى لا تضيع الطلبات والحسابات عند إعادة إنشاء الحاوية. كما يجب ضبط `JWT_SECRET` ويفضل ضبط `ADMIN_PASSWORD` صراحةً.

## حالة النسخة الحالية
**خدمات 2.13.0 — تحديث أيقونات التثبيت مع تحسينات مقدم الخدمة السابقة.**

تتضمن هذه النسخة فتح أقسام مقدم الخدمة في نوافذ منبثقة بدل القفز الطويل داخل الصفحة، وقوائم منسدلة لتوثيق الهوية والترخيص، وحفظ نوع الهوية المحدد، وإغلاق قائمة القدرات تلقائيًا بعد الحفظ. كما تحافظ على ضوابط مهام التنفيذ والصلاحيات، وسلامة المدخلات والمرفقات، واتساق وجهة المشوار والأجرة وسجل الدفع النقدي. الدفع الإلكتروني غير مفعّل ومؤجل إلى مرحلة مستقلة بعد اكتمال الوظائف الأساسية.

هذه الحزمة الحالية تستخدم `Node.js + TypeScript + SQLite` وواجهات PWA. لا يجوز اعتبار نجاح الاختبارات الآلية وحده بديلًا عن اختبار التشغيل على بيئة تجريبية، أو مراجعة أمنية مستقلة، أو التحقق من إعدادات الإنتاج والخدمات الخارجية. راجع `PRELAUNCH_CHECKLIST_2.13.md` قبل أي إطلاق.

## سجل التحقق الحالي
- تم التحقق من صحة JSON لملفات manifest الأربعة، ومن وجود ملفات الأيقونات وأبعادها المطلوبة (192×192 و512×512، وأيقونة متصفح 64×64).
- تم التحقق من اتساق رقم الحزمة `2.13.0`، وروابط الأصول `v=2.13`، ومفتاح Service Worker `khadamat-shell-v2-13`.
- لم تُشغّل مجموعة الاختبارات كاملة في بيئة إعداد هذا الإصدار: لا توجد تبعيات مثبتة أو ملف lock، وتعذّر إكمال تثبيت الحزم ضمن المهلة المتاحة. أُضيف اختبار آلي جديد لأرقام الإصدار وملفات الأيقونات، ويجب تشغيل `npm install` ثم `npm test` في بيئة متصلة قبل النشر.
- لم يُنشر الإصدار على Railway ولم تُختبر الأيقونات بصريًا على هاتف فعلي بعد.

التحقق أعلاه لا يغطي بعد اختبار حمل إنتاجي أو اختبار اختراق مستقل أو تأكيد إرسال WhatsApp OTP من حساب أعمال فعلي أو اختبار التوجيه الخارجي في بيئة الإطلاق؛ لذلك لا تُعد هذه النسخة إعلان اكتمال نهائي.

## إعدادات البيئة
انسخ:

```bash
cp .env.example .env
```

على Windows يمكنك نسخ الملف يدويًا باسم `.env`.

أهم الإعدادات:

- `NODE_ENV`
- `PORT`
- `DB_PATH`
- `UPLOAD_DIR`
- `JWT_SECRET`
- `ACCESS_TTL_SEC`
- `REFRESH_TTL_DAYS`
- `CORS_ORIGINS`
- `ADMIN_NAME`
- `ADMIN_PHONE`
- `ADMIN_EMAIL`
- `ADMIN_PASSWORD`

في الإنتاج يجب استخدام `JWT_SECRET` قويًا وعدم استخدام بيانات المدير التجريبية.

## حدود التشغيل والتوسع

هذه النسخة تعمل حاليًا بـ `Node.js + TypeScript + SQLite` مع واجهات PWA مستقلة للعميل ومقدم الخدمة والإدارة. تشغيلها في مرحلة تجريبية أو إطلاق محدود يحتاج إلى تخزين دائم، ونسخ احتياطي قابل للاستعادة، وHTTPS، وضبط أسرار الإنتاج، واختبارات تشغيل موثقة.

SQLite ومحدد المعدل الموجود في الذاكرة مناسبان لتشغيل نسخة واحدة ضمن حدود حمل واضحة، لكنهما ليسا إعدادًا للتوسع الأفقي متعدد النسخ دون تغييرات. قبل التوسع الكبير أو تشغيل عدة نسخ متوازية، ينبغي نقل قاعدة البيانات إلى PostgreSQL واستبدال المحدد/الجدولة المشتركة بمكونات موزعة مثل Redis/Queue، مع اختبارات ترحيل وتزامن مستقلة. هذا تحسين بنيوي للتوسع، وليس ادعاءً بأن هذه المكونات موجودة بالفعل في الحزمة الحالية.

## واجهات الويب المضافة
- `http://localhost:3000/` واجهة العميل
- `http://localhost:3000/provider.html` واجهة مقدم الخدمة
- `http://localhost:3000/admin` لوحة الإدارة
- `http://localhost:3000/health` فحص صحة الخادم

لبيانات التطوير المحلية لأول تشغيل استخدم:
`npm run seed:demo`

حسابات العرض التجريبي:
- العميل: `customer@demo.local` / `Demo12345`
- مقدم الخدمة: `provider@demo.local` / `Demo12345`

بيانات المدير تُحدد عبر `ADMIN_NAME`, `ADMIN_PHONE`, `ADMIN_EMAIL`, `ADMIN_PASSWORD` في `.env` أو تُنشأ كلمة مرور عشوائية عند أول seed إذا لم تُحدد.
